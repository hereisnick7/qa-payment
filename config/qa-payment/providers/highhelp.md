# HighHelp — карточка провайдера (пример)

Пример заполненной карточки: только факты о самом провайдере, наблюдённые на
реальном прогоне. Пути и коды ошибок вашего бэка будут свои.

## Интеграция
- Методы приёма (пример UZS): карточный p2p (`payin-p2p-card` + `payment_system`),
  1-click (`payin-1-click`, без payment_system). Выплата: `card-p2p`, карта 16 цифр;
  платёжную систему провайдер определяет по номеру карты.
- Ответ на создание и депозита, и выплаты: **201** + `processing` (+ `form_url` у
  депозита) — бэк обязан принимать 201 на обоих путях (класс B1).
- Суммы в минорных единицах (×100).

## Вебхуки
- Подпись: RSA SHA256 PKCS1v15 над `base64url(";".join(sorted(normalize(body)))) + ts`,
  заголовки `x-access-signature` (base64url) + `x-access-timestamp`.
  Адаптер: `workflow pay-hook highhelp`. Асимметричная схема → для синтетики нужна
  подмена ключа проверки на DEV.
- Тело: `project_id`, `general{request_id, payment_id}`, `status{status}`,
  `payment_info{amount, currency[, initial_amount — только депозит]}`.
- `payment_id` в хуке выплаты = ID операции мерчанта.
- Статусы: `success`, `decline`, `error`, `processing`, `dispute`.

## Особенности стенда / провайдера
- На тестовом окружении карточные методы быстро отбиваются «Requisites not found»;
  1-click живёт ~10 мин до таймаута, потом приходит cancel-хук.
- Тестовые платежи в чате поддержки провайдера подтверждают неохотно → синтетика.

## Прод (что видно после релиза)
- `processing` и `decline` провайдер шлёт один раз, без ретраев; `dispute` и
  `success` — с ретраями (success по одной заявке может прийти дважды → проверять,
  что баланс начислен ровно один раз).
- Тестовые прод-платежи может резать антифрод провайдера: decline с
  `status_description: "Anti-fraud declined"` через несколько секунд после
  создания (вероятная причина — VPN-IP, не совпадающий со страной метода).
- В хуке `lifetime` (секунды) — время жизни заявки; отличает истечение от отказа.
- Если провайдер жалуется «колбэки не доставлены» — сначала смотреть коды
  наших ответов (неверные ключи на старте → массовый 400 по подписи).
